你现在要修改仓库 manus_vive_com。

目标：
新增一个最小 raw JSONL capture 功能，用于保存真实 MANUS + Vive Tracker 通讯数据，供另一个仓库 exp2 回放和解析。

重要背景：
这个仓库目前已经有 C++ SDK client 通过 TCP 发送 combined JSON。
Python 侧 manus_data_receiver.py 能接收 JSON，并在 _process_frame(frame_data) 中处理每帧数据。
现在不要重写 SDK、不要重写通讯协议、不要做新的融合算法。
只需要把接收到的原始 frame_data 按 JSONL 保存。

但是有一个关键要求：
当前 combined JSON 的 timestamp 可能只是 MANUS skeleton 和 Vive tracker 混合后的组合时间戳。为了后续判断两路数据是否同步，需要同时保留：
1. combined timestamp：打包/发送这一帧的时间
2. skeleton timestamp：最新 skeleton 数据的接收时间或设备时间
3. tracker timestamp：最新 tracker 数据的接收时间或设备时间

如果 MANUS SDK / Tracker SDK 没有提供真实设备时间戳，那么至少记录你程序收到各自 callback 的时间，例如 steady_clock / perf_counter 时间。不要只保留 combined timestamp。

============================================================
一、raw JSONL 保存
============================================================

1. 修改 manus_data_receiver.py

给 ManusDataReceiver 增加可选参数：
- raw_jsonl_path: str | None = None
- flush_raw_jsonl: bool = True

如果 raw_jsonl_path 不为 None：
- 在 start 或初始化时打开文件
- 每次 _process_frame(frame_data) 成功解析到一帧 raw dict 后，把原始 frame_data 写入 JSONL
- 每帧一行 json.dumps(frame_data, ensure_ascii=False)
- 如果 flush_raw_jsonl=True，每帧后 flush，保证中途崩溃也尽量保留数据
- stop / close 时关闭文件

注意：
- 保存的是原始 combined JSON frame_data，不要改写字段，不要先转换成 CSV。
- 不要只保存 data_buffer，因为 data_buffer 可能只保存最近 N 帧。
- 不要让 raw capture 影响 latest_data、latest_tracker_data、data_buffer 的原有行为。
- 如果写文件失败，要打印清晰错误，但不要让 receiver 无提示崩溃。
- 保持向后兼容：raw_jsonl_path=None 时行为和以前一致。

============================================================
二、时间戳要求
============================================================

请尽量让每一行 raw JSONL 里包含这些字段：

推荐顶层字段：
- timestamp 或 combined_timestamp
  表示 combined JSON 打包/发送的时间
- frame 或 combined_frame
  表示 combined frame id
- skeleton_timestamp
  表示 skeleton 数据本身的采样时间、SDK 时间，或 skeleton callback 到达程序的时间
- tracker_timestamp
  表示 tracker 数据本身的采样时间、SDK 时间，或 tracker callback 到达程序的时间
- skeleton_frame
  如果可用，表示 skeleton 数据自己的帧号
- tracker_frame
  如果可用，表示 tracker 数据自己的帧号

如果已经有 timestamp / frame 字段，为兼容 exp2，可以继续保留：
- timestamp = combined timestamp
- frame = combined frame id

然后新增：
- skeleton_timestamp
- tracker_timestamp
- skeleton_frame
- tracker_frame

如果 C++ 端当前缓存 latest skeleton 和 latest tracker：
- 缓存数据时也缓存各自 timestamp / frame id
- 组合 JSON 时把这些字段一起带上

如果 SDK 没有原始 timestamp：
- skeleton_timestamp 使用 skeleton callback 到达程序时的 steady_clock 时间
- tracker_timestamp 使用 tracker callback 到达程序时的 steady_clock 时间
- combined_timestamp 使用打包/发送 combined frame 时的 steady_clock 时间

不要在这一阶段做复杂同步、插值、重采样。
只需要记录时间戳，后续 exp2 会计算 sync_delta。

============================================================
三、新增 capture_raw_jsonl.py
============================================================

增加命令行脚本 capture_raw_jsonl.py。

功能：
启动 ManusDataReceiver，并保存 raw_frames.jsonl。

建议参数：
- --host 默认 127.0.0.1
- --port 默认 8888
- --out 默认 data/raw_frames.jsonl
- --duration 可选，采集多少秒后停止
- --max-frames 可选，采集多少帧后停止
- --flush 默认 True
- --print-every 默认 30，每 N 帧打印一次统计

脚本行为：
- 启动 receiver
- 等待 C++ client 连接并发送数据
- 持续保存 raw JSONL
- 到 duration 或 max_frames 后停止
- Ctrl+C 时也要优雅关闭文件
- 最后打印：
  - total frames received
  - output path
  - elapsed time

============================================================
四、新增 inspect_raw_jsonl.py
============================================================

增加一个简单验证脚本 inspect_raw_jsonl.py。

输入：
- --path raw_frames.jsonl

输出统计：
- total lines
- valid json lines
- frames with skeletons
- frames with trackers
- frames with node 4
- frames with node 9
- frames with tracker position
- frames with tracker valid=true
- frames with skeleton_timestamp
- frames with tracker_timestamp
- first combined timestamp
- last combined timestamp
- first skeleton timestamp
- last skeleton timestamp
- first tracker timestamp
- last tracker timestamp
- if possible: min/mean/max abs(skeleton_timestamp - tracker_timestamp)

这个脚本只检查 raw JSONL 结构，不要依赖 exp2。
